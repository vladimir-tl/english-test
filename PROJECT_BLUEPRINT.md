# Экспорт устройства проекта

Этот документ можно передать разработчику или другому ИИ как спецификацию для нового проекта с тем же визуальным языком и устройством карточек. Описано текущее состояние репозитория, без предположений о будущем дизайне.

## Короткое ТЗ для переноса

> Собери новый интерфейс в стиле этого проекта: спокойный светлый фон, центрированный контент, белые карточки с тонкой границей и скруглением 16 px, синий акцент, системный шрифт, простые элементы без теней. Поддержи автоматическую тёмную тему через `prefers-color-scheme`. Основной интерактивный сценарий размести в одной карточке шириной до 640 px, переключая внутри неё состояния `intro → quiz → result`. Для вариантов выбора используй кнопки на всю ширину с тонкой рамкой, а выбранный вариант выделяй синей рамкой и внутренним контуром. Данные, локализацию и визуальный каркас держи отдельно. Ниже приведены точные параметры и структура.

## Технология и структура

- Astro 7, TypeScript, статическая генерация страниц. Сторонней UI-библиотеки и CSS-фреймворка нет.
- `/` перенаправляет на `/ru`; страницы есть для `ru`, `en`, `et`: `/{lang}` и `/{lang}/test`.
- `src/layouts/Base.astro` — HTML-оболочка, переключатель языков, глобальные токены и общие стили.
- `src/pages/[lang]/index.astro` — адаптивный первый экран с текстом, CTA и SVG-иллюстрацией.
- `src/components/LevelSteps.astro` — самостоятельная SVG-иллюстрация карточек уровней.
- `src/pages/[lang]/test.astro` — разметка одной карточки и клиентская логика её состояний.
- `src/data/questions.ts` — вопросы, типы данных и пороги результата.
- `src/i18n/ui.ts` — словарь интерфейса для трёх языков. Содержание вопросов остаётся английским.
- `public/audio/` — два MP3-файла для аудиовопросов.

Поток данных: `questions + thresholds + ui[lang]` сериализуются серверной страницей в `data-config` корневой карточки. Встроенный клиентский скрипт читает эти данные и обновляет DOM без переходов между вопросами и без серверного API.

## Визуальная система

Шрифт: `system-ui, sans-serif`, базовый размер `16px`, межстрочный интервал `1.5`. Макет с `box-sizing: border-box`. Теней у интерфейсных карточек нет; глубину дают фон, тонкая рамка и свободное пространство.

| Токен | Светлая тема | Тёмная тема | Назначение |
| --- | --- | --- | --- |
| `--bg` | `#f7f8fa` | `#12151c` | фон страницы |
| `--fg` | `#1c2333` | `#e8ebf2` | основной текст |
| `--card` | `#ffffff` | `#1b2030` | поверхность карточки |
| `--accent` | `#3b5bdb` | `#7c93ff` | CTA, выбор, прогресс, результат |
| `--ok` | `#2b8a3e` | `#51cf66` | правильный ответ |
| `--bad` | `#c92a2a` | `#ff6b6b` | неверный ответ |
| `--muted` | `#6b7280` | `#9aa3b5` | вспомогательный текст |
| `--line` | `#dfe3ea` | `#2b3245` | рамки и разделители |

Тёмная тема включается системным медиа-запросом `@media (prefers-color-scheme: dark)`, без ручного переключателя.

### Размеры и ритм

| Элемент | Точные правила |
| --- | --- |
| Основной контейнер | `max-width: 920px; margin: 0 auto; padding: 0 16px 48px` |
| Основная карточка | `max-width: 640px; margin: 0 auto; padding: 24px; border: 1px solid var(--line); border-radius: 16px; background: var(--card)` |
| Кнопка действия | `padding: 10px 20px; border-radius: 10px; background: var(--accent); color: #fff` |
| Вариант ответа | ширина `100%`, `padding: 10px 14px`, рамка `1px`, радиус `10px`, прозрачный фон |
| Список вариантов | CSS grid, `gap: 8px`, отступы `16px 0` |
| Поле короткого ответа | те же рамка, радиус и внутренние отступы, что у варианта |
| Прогресс | ширина `100%`, высота `8px`, `accent-color: var(--accent)` |
| Текст вопроса | `1.35rem`, верхний отступ `16px` |
| Значение результата | `3rem`, жирное, цвет `var(--accent)` |
| Строка разбора | `padding: 8px 0`, верхний разделитель `1px solid var(--line)` |

Выбранный вариант имеет `aria-pressed="true"`, синюю рамку и `box-shadow: 0 0 0 2px var(--accent) inset`. Поле ответа получает тот же контур при фокусе. Неактивная основная кнопка имеет `opacity: .4` и `cursor: not-allowed`.

## Архитектура карточек

В текущем коде **одна** `.card` содержит три секции: `#intro`, `#quiz`, `#result`. Скрипт показывает нужную секцию через атрибут `hidden`. Вопросы не создают новые карточки и не меняют URL.

```text
Base layout
└── main, до 920 px
    └── .card, до 640 px
        ├── #intro: заголовок → описание → кнопка «Начать»
        ├── #quiz: прогресс → счётчик → [аудио] → вопрос
        │          → варианты-кнопки ИЛИ текстовое поле → «Далее»
        └── #result: уровень → описание → счёт → разбор → «Повторить»
```

Для переноса карточки как паттерна:

```html
<main>
  <div class="card">
    <section id="intro">...</section>
    <section id="quiz" hidden>...</section>
    <section id="result" hidden>...</section>
  </div>
</main>
```

Карточка опирается на **глобальные** классы из `Base.astro`: `.card`, `.btn`, `.options`, `.opt`, `.gap`, `.prompt`, `.muted`, `.level`, `.rev`, `.ok`, `.bad`. Это важно при переносе в систему со стилями, ограниченными компонентом: стили нужно импортировать в корневой слой или перенести в компонент явно.

### Поведение

1. `start` обнуляет номер вопроса и ответы, открывает `quiz`.
2. `renderQuestion` обновляет прогресс, счётчик, вопрос, аудио и поле ответа или варианты. Кнопка «Далее» заблокирована, пока ответа нет.
3. Вариант хранится как индекс; текстовый ответ — как строка. Ввод можно подтвердить клавишей Enter.
4. Последний ответ открывает результат: число правильных ответов, уровень по порогам и полный разбор.
5. `retry` возвращает на вступление; повторный `start` создаёт новую попытку.

Для текстовых ответов сравнение не учитывает регистр, краевые пробелы, повторные пробелы, конечные `.` и `!`, а также разные апострофы. Для вариантов ответа сравниваются индексы.

### Модель данных

```ts
type Level = 'A1' | 'A2' | 'B1' | 'B2';

interface Question {
  level: Level;
  prompt: string;
  options: string[];  // пустой массив для текстового ответа
  answer: number;     // индекс варианта; -1 для текстового ответа
  accept?: string[];  // допустимые текстовые ответы
  audio?: string;     // путь к MP3 в public/
}
```

Текущий тест содержит 21 вопрос: варианты выбора, короткий ввод и аудирование. Пороги по числу правильных ответов идут по убыванию: `B1 ≥ 16`, `A2 ≥ 11`, `A1 ≥ 6`, иначе `A0` (показывается как `< A1`). В данных есть вопросы уровня `B2`, но результат выше `B1` сейчас не выдаётся. Если в новом проекте нужна иная шкала, её следует отдельно определить вместе с текстом вступления.

## Первый экран

На мобильной ширине это один столбец; с `760px` — сетка из двух столбцов `1.1fr 1fr` с промежутком `32px`. Слева: метка `18+` с рамкой, крупный заголовок `clamp(2.2rem, 7vw, 3.4rem)` и `line-height: 1.1`, серый подзаголовок и синяя CTA. Справа: SVG шириной до `360px`, центрированный в своей области. В заголовке выделенное слово синее, но без курсива.

Иллюстрация повторяет язык карточек: светлая поверхность, тонкий контур, три строки уровней A1/A2/B1 со скруглением, активная строка с полупрозрачным синим фоном и более сильной рамкой. Она встроена как SVG, не зависит от внешней картинки.

## Как применить в другом проекте

1. Перенести таблицу токенов и правила основного контейнера, карточки, кнопок, вариантов, поля и прогресса. Для буквального совпадения взять CSS из `src/layouts/Base.astro`.
2. Создать оболочку страницы и один компонент карточки с тремя состояниями. Для нового сценария переименовать состояния по смыслу, сохранив размещение внутри одной поверхности.
3. Вынести предметные данные и словари интерфейса из компонента. Передавать в него данные явно; не встраивать тексты в обработчики событий.
4. Сохранить логику выбора, отключённой кнопки, прогресса, результата и разбора; заменить критерии оценки под задачу нового проекта.
5. Для первого экрана использовать двухколоночный макет с порогом `760px`, если он нужен в новом проекте.

Исходники для точного копирования: `src/layouts/Base.astro`, `src/pages/[lang]/test.astro`, `src/pages/[lang]/index.astro`, `src/components/LevelSteps.astro`, `src/data/questions.ts`, `src/i18n/ui.ts`.

## Релиз: Cloudflare Pages, english-test.ee

Настройки проекта в Cloudflare Pages: framework preset `Astro`, build command `npm run build`, output directory `dist`. Версию Node задаёт `.node-version` (22).

Что уже есть в репозитории:

- `astro.config.mjs`: `site: https://english-test.ee`, `build.format: 'file'` и `trailingSlash: 'never'` дают чистые адреса без слеша (`/ru/topics` → `ru/topics.html`).
- `src/layouts/Base.astro`: `description`, `canonical`, `hreflang` (ru/en/et + x-default → ru), Open Graph, Twitter card, favicon, JSON-LD через проп `jsonLd`.
- `src/pages/sitemap.xml.ts`: все страницы на трёх языках с `xhtml:link` альтернативами. `public/robots.txt` ссылается на него.
- `src/pages/404.astro`: Cloudflare Pages отдаёт `404.html` автоматически.
- `public/_redirects`: `/` → `/ru` (301). `public/_headers`: заголовки безопасности, долгий кеш для `/_astro/*`, `noindex` для `*.pages.dev`.
- `scripts/make-images.mjs`: пересобирает `favicon-32.png`, `apple-touch-icon.png` и `og.png` из `public/favicon.svg`.

После первого деплоя:

1. Подключить домен `english-test.ee` в Pages → Custom domains; `www.english-test.ee` перенаправить на основной домен правилом Redirect Rules (или Bulk Redirects) в Cloudflare.
2. Добавить сайт в Google Search Console и Bing Webmaster Tools, отправить `https://english-test.ee/sitemap.xml`.
3. Проверить разметку в Rich Results Test и превью ссылок (например, в Telegram или через opengraph.xyz).
